# UI 완료 확인

## 1. 찍을 대상 정하기

- 바꾼 화면이 속한 기능을 정한다. 등록된 기능은 `apps/web/e2e/screens/*.json`(파일 이름 = 기능).
- 새 화면이면 해당 기능의 JSON에 항목을 추가한다. 형식:
  ```json
  { "name": "<기능>-<상태>", "path": "/경로?쿼리", "waitFor": "화면에 반드시 보이는 문구" }
  ```
  `waitFor`는 데이터가 다 그려진 뒤에만 나타나는 문구로 고른다. 상태별 화면은 쿼리(`?demo=`, `?at=` 등)로 고정한다.
- 공용 컴포넌트라면 `/__ui` 카탈로그에 예시를 넣고 `ui` 기능으로 찍는다.

## 2. 촬영

```sh
SNAP_ONLY=<기능>[,<기능>…] pnpm ui:snap
```

- 다른 작업이 동시에 ui:snap을 돌릴 수 있으면 `SNAP_PORT=<5180이 아닌 포트>`를 준다.
- 실패하면(가로 스크롤 `scrollWidth > innerWidth`, 콘솔 에러, `waitFor` 시간 초과) 원인을 고치고 다시 찍는다. 테스트를 느슨하게 바꾸지 않는다.

## 3. PNG 직접 보기

결과는 `apps/web/.snap/<이름>.<desktop|narrow>.<light|dark>.png`. 바꾼 화면마다 **네 장 모두** Read로 열어 확인한다.

- 라이트·다크 둘 다에서 글자와 배경 대비, 하드코딩된 색 흔적(한쪽 테마에서만 튀는 색)
- 좁은 폭(390px)에서 잘림·겹침·줄바꿈
- 판정은 `VerdictBadge`로 글자와 함께 보이는지
- 디바이스 화면(`MockScreen`) 안이 테마에 따라 바뀌지 않는지

## 4. 보고

찍은 화면 목록과 직접 확인한 내용, 남은 문제를 짧게 알린다. 확인하지 않은 PNG를 확인했다고 하지 않는다.
