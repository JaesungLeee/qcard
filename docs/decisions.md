# 결정 기록

되돌리기 어렵거나, 코드만 봐서는 이유를 알 수 없는 결정을 모았다. 결정을 바꾸면 이 문서를 고치고, 바꾼 이유를 남긴다. 그때그때의 상세한 논의는 git 이력의 `docs/PRD.md`(v0.1~v0.20, 2026-10-15~10-30)에 있다.

## 제품 범위

### 여러 팀이 쓰는 서비스, 프로젝트 = QA 대시보드

처음에는 한 팀 전용이었지만, 앱 프로젝트마다 대시보드를 만들고 멤버를 초대해 쓰는 서비스로 바꿨다. 조직 계층은 두지 않는다. 프로젝트가 멤버·권한·데이터의 단위이고, 프로젝트 간 격리는 보안 규칙으로 강제한다.

### Android만, iOS는 나중에

iOS는 시뮬레이터·실기기, WebDriverAgent 서명, Apple Developer 계정, 시뮬레이터용 빌드 수급까지 범위가 크다. MVP는 Android에 집중하고, 플랫폼 필드와 `DeviceDriver` 추상화를 남겨 둔다.

### 범위 밖

웹·데스크톱 앱 테스트(앱 안의 WebView는 지원), 성능·부하·보안 침투 테스트, 픽셀 단위 시각 회귀, 디바이스 팜 구축, 원격 실행·다중 관전, 소스코드 기반(화이트박스) 테스트.

## 아키텍처

### 실행·관찰은 로컬, 결과만 클라우드

라이브 화면은 실행자 한 명만 보면 된다. 영상을 서버로 중계하지 않으면 미디어 서버·NAT·대역폭 문제가 없어진다. 팀은 진행 상태를 실시간으로, 화면은 스크린샷으로 본다. 원격 관전 수요가 생기면 호스트에 관리형 SFU를 붙인다.

### Firebase, 자체 서버 없음

1인 프로젝트라 서버 운영을 없앴다. Firestore 실시간 구독이 진행 상태 공유에 맞고, 보안 규칙으로 프로젝트 격리와 역할을 강제할 수 있다. 서울 리전.

### TypeScript 단일 언어 모노레포

웹·Functions·호스트가 같이 바뀌는 제품이라 스키마를 타입 정의 하나(Zod)로 공유한다. ADB는 언어와 무관하다.

### Appium 대신 ADB 직접 호출

`uiautomator dump`와 `input`이면 충분하고 설치 부담이 없다. Appium이 필요해지면 `DeviceDriver` 뒤에 붙인다.

### 호스트는 macOS만

실행자 PC가 모두 macOS였다. 키체인에 호스트 자격을 둔다.

## LLM

### LLM은 사용자 본인의 Claude Code로

| 선택지                                        | 결과                                                                                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| A. Anthropic API 키 + 클라우드 LLM 프록시     | 처음 채택. 비용을 운영자가 내거나 공용 키가 필요해 "사용자별 본인 플랜 부담"과 맞지 않아 제외. API 키 구현은 개발·테스트용으로만 남김 |
| B. Bedrock / Vertex AI                        | API 과금 경로라 고려하지 않음                                                                                                         |
| C. 사내 호스팅 모델                           | 미채택                                                                                                                                |
| **D. 사용자 본인의 Claude Code(`claude -p`)** | **채택.** 각 사용자의 구독 플랜에서 차감                                                                                              |

D를 고른 결과로 LLM 작업(QA 문서 생성, 수정안)이 모두 요청자의 호스트로 옮겨 갔고, 클라우드 LLM 프록시와 프로젝트 월 예산 상한이 사라졌다. 경계와 정책 조건은 [security.md](security.md#llm-호출-경로).

### 플랜 로그인만 지원

Console 계정·API 키·Bedrock·Vertex(API 크레딧 과금)는 지원하지 않는다. 구독 정책이 바뀌어 D가 막히면 API 크레딧 경로로 옮기지 않고 제품 방향을 다시 정한다.

### Verifier를 Executor와 분리하고 Sonnet 고정

같은 모델이 행동하고 판정하면 자기확증 편향이 생긴다. 판정 품질이 실행 모델 선택에 흔들리지 않게 Verifier 모델을 고정한다.

### 트리 포인트는 LLM이 찾고 코드가 비교한다

LLM이 값까지 판정하면 거짓 Pass가 생긴다. LLM은 대상 요소만 찾고, 텍스트·개수·크기 비교는 코드가 한다.

## QA 문서

### 앱 버전별 QA 문서, 기준은 Firestore 케이스 문서

MD 파일을 기준으로 두면 동시 편집·승인 해시·결과 연결이 어렵다. 케이스 단위 Firestore 문서를 기준으로 두고 웹에서만 편집한다(낙관적 잠금).

### 케이스는 TS·EC 행에서만

스펙 전체에서 케이스를 상상해 만들면 버전마다 결과가 흔들리고 승인 부담이 커진다. 스펙 작성자가 적은 시나리오 행에서만 만들고, 빠진 것은 스펙 보강 제안으로 스펙 작성자에게 돌려보낸다. 같은 이유로 스펙 이미지 해석은 미뤘다.

### 출처 ID로 결정적 매칭, 바뀌지 않은 케이스는 복사

LLM 매칭은 비결정적이다. 출처 ID + 내용 해시로 매칭하고, 같으면 LLM 없이 복사해 사람의 수정·승인을 지킨다. 전제는 스펙 작성자가 TS·EC ID를 다시 쓰지 않는 것이다.

### 준비 플로우는 QA 문서 버전마다 사본

처음에는 프로젝트 공용 목록이었다. 이전 버전으로 돌리는 사이클(1.0.1 다음 1.0.0)이 새 버전의 플로우를 쓰게 되고, 쓰이지 않는 플로우가 쌓여서 바꿨다. 대신 로그인 플로우처럼 여러 버전에 같은 수정이 필요하면 버전마다 고쳐야 한다.

### 계정 풀은 케이스의 필요 계정 종류로만

프로젝트 플래그를 두면 설정과 케이스가 어긋날 수 있다. "로그인 필요"만 두면 유료·권한 케이스를 자동화할 수 없고, 계정을 직접 지정하면 병렬 실행·격리 때 대체가 안 된다. 그래서 케이스에 계정 **종류**를 두고, 로그인 상태는 준비 플로우로 나눴다. 멤버 역할과 헷갈리지 않게 "계정 종류"라 부른다.

### 테스트 계정 비밀값은 서버(KMS)에

실행자 PC 키체인에 두는 안도 봤지만, PC마다 입력해야 하는 부담이 컸다. 웹에서 한 번 등록하고, 배정받은 실행자 호스트에만 전달한다.

## 실행

### 위험 액션은 결과 기준 두 등급

버튼 종류(삭제·결제 버튼)로 보면 놓치는 것이 많다. 액션의 결과로 판별하고, Agent가 해도 되지만 확인이 필요한 **승인 필요**와 Agent가 하면 안 되는 **사람 전용**으로 나눴다. Agent 판단만으로는 놓칠 수 있어 코드 안전장치를 함께 둔다.

### 자동 확정은 좁게

거짓 Pass가 가장 비싼 오류다. 모든 포인트 일치 + 트리로만 확인 + 개입 없음 + 자가 복구 한도 안일 때만 자동 확정한다. 비전 판정의 일치율이 쌓이면 완화를 검토한다.

### 실행 환경 문제는 Blocked가 아니라 일시정지

플랜 한도·로그인 만료·디바이스 연결 끊김은 케이스 결함이 아니고 시간이 지나거나 사람이 고치면 풀린다. Blocked로 두면 남은 케이스가 줄줄이 Blocked가 된다. 재개 때는 진행 중이던 케이스를 처음부터 다시 돈다.

### 녹화 대신 스텝별 스크린샷

판정 추적은 액션 표시 스크린샷으로 된다. 영상을 쓰는 동기화 재생이 필요해질 때 녹화를 함께 만든다.

## 웹·협업

### 로그인은 GitHub 단일, 웹에서만

대상 사용자(앱 개발 팀)는 GitHub 계정이 있다. Google 로그인은 같은 이메일의 계정 충돌 처리와 초대 기준(GitHub 사용자명) 분리 부담이 있어 넣지 않았다. 호스트는 따로 로그인하지 않고 웹에서 연결해, 호스트에 GitHub 토큰을 두지 않는다.

### QA 시트는 웹 전용

XLSX를 기준으로 두면 실시간 공유·판정 이력을 지킬 수 없다. 내보내기는 필요할 때 같은 구조로 만든다.

### 공유 링크 = 화면 주소

별도 공유 버튼·리포트 화면·공개 링크 없이, 화면마다 고유 주소를 두고 보안 규칙으로 막는다(2026-10-26).

### 결함 트래커는 GitHub Issues

대상 사용자가 GitHub을 쓴다. 지금은 qcard 안에서 결함을 등록·관리하고, Issues 발행은 로드맵에 있다.

### 빌드는 서명된 APK를 웹으로 올린다

재서명하지 않고 그대로 설치해 테스트한 파일 = 배포 파일을 보장한다. AAB·CI 자동 수급은 나중이다.
