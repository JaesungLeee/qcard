# 테스트 사이클

여러 실행자가 각자의 디바이스로 돌린 Run을 결과 하나로 묶는 단위다. QA 시트·요약·통과율은 사이클 단위로 계산한다.

코드: 규칙 `packages/shared`·`packages/data/src/logic.ts`, 칸 선점·삭제 `apps/functions`, 실행 `apps/host-agent/src/runCycle.ts`, 화면 `apps/web/src/features/qa-sheet`.

## 생성

- QA 문서 버전 + 빌드 + **대상 디바이스 목록(모델 + OS 메이저 버전)**을 고른다.
- 실제 디바이스는 모델과 OS 메이저 버전이 같으면 같은 대상이다. 정확한 OS 빌드·보안 패치는 결과에 남긴다.
- 대상 목록에 없는 디바이스로는 실행하지 않는다.
- **케이스 스냅샷**: 만들 때 승인된 케이스(TC ID + 내용 해시)와 그 내용을 사이클에 복사한다. 그 뒤 QA 문서가 바뀌어도 사이클은 복사한 내용으로 돈다. 스냅샷과 사이클의 빌드는 바꿀 수 없다.

### 빌드

- **서명된 APK만** 웹에서 올리고 Storage로 공유한다. qcard는 재서명하지 않고 그대로 설치한다(테스트한 파일 = 배포 파일).
- 버전·빌드 번호·패키지명·서명 지문은 파일에서 자동으로 읽는다(`packages/apk`).
- 호스트는 사이클 빌드를 내려받아 캐시하고 설치한다. 모든 실행자가 같은 파일을 설치한다.

## Run 시작

Run을 시작하는 곳은 둘이고, 실행 위치는 늘 실행자 본인의 호스트다.

- **웹 QA 시트 머리**의 [내 호스트에서 실행]·[이어서 실행]: 작업(`run_cycle`)을 만들고 **요청자 본인의 호스트**가 받아 로컬 콘솔과 같은 경로로 시작한다. 호스트가 꺼져 있으면 켜는 방법을 안내하고, 폰이 잠겼거나 다른 Run이 진행 중이면 작업을 실패로 남긴다.
- **로컬 콘솔 홈**.

### 실행 케이스 고르기

- 기본값은 **이 디바이스의 남은 칸 전체**다(결과가 있는 칸은 건너뜀).
- [케이스 고르기]에서 일부만 고른다. 대상은 자동 케이스만이다(Run은 수동 케이스를 돌리지 않는다).
- 판정 필터는 **이 디바이스 칸 기준**(남은 칸·Fail·Blocked·확인필요·전체)이고 다른 기기의 결과는 보지 않는다. 우선순위 필터도 있다.
- 목록은 **기능(스펙, TC ID 접두어) → 세부 기능**으로 묶어, 묶음 체크로 한꺼번에 또는 하나씩 고른다. 묶음 체크와 "걸러진 것 모두 고르기"는 걸러진 케이스에만 적용된다.
- 결과가 있는 칸에는 지금 판정과 "다시 실행"을 보이고, 고르면 다시 실행한다.
- 웹 QA 시트와 로컬 콘솔이 같은 화면·규칙(`apps/web/src/components/case-pick/`)을 쓴다. 웹에서 고르면 작업 입력 `tcIds`로 넘긴다.

## 재실행

같은 케이스·같은 디바이스를 다시 돌리면 **최신 결과가 최종**이고, 이전 시도는 이력으로 남긴다(리포트에 "재시도 N회").

## 칸 자동 선점

같은 대상 디바이스를 여러 명이 나눠 돌릴 때 같은 칸을 두 번 돌리지 않게 한다.

- 케이스를 시작하는 순간 그 칸(케이스 × 대상 디바이스)을 잠근다. 같은 대상으로 실행 중인 다른 Run은 잠긴 칸과 끝난 칸을 건너뛰고 남은 칸을 가져간다.
- **잠금은 Run 문서의 지금 칸(`currentTcId`)이다.** Functions(`claimCell`)가 같은 대상 디바이스의 Run들과 그 칸의 결과를 트랜잭션에서 읽고 정한다. 호스트는 지우기만 할 수 있다(보안 규칙).
- 칸을 잡은 Run = 실행 중이고 연결 신호가 90초(`RUN_STALE_MS`) 안에 있는 Run. 케이스 종료·Run 중단·연결 신호 만료면 잠금이 풀린다. 이 신호는 테스트 계정 리스와 같다.
- 일시정지된 Run은 칸을 놓는다(진행 중 케이스 결과를 쓰지 않으므로).
- 호스트는 **앞 케이스 결과를 올린 뒤** 다음 칸을 잡는다(결과가 큐에 남은 채 칸을 옮기지 않게). 칸을 잡지 못할 만큼 네트워크가 끊기면 "네트워크 끊김"으로 일시정지한다.
- 연결 신호는 **업로드 큐를 거치지 않고** 바로 보낸다. 밀린 업로드 때문에 살아 있는 Run의 칸을 뺏기지 않게 하려는 것이다.
- 케이스 도중 신호를 60초 넘게 남기지 못했으면(네트워크 끊김·PC 절전) 다른 Run이 가져갔을 수 있으므로, 다음 턴에서 멈추고 결과를 버린 뒤 "호스트 연결 끊김"으로 일시정지한다. 남이 가져간 칸에 플랜 사용량을 쓰지 않게 하려는 것이다.
- 건너뛴 칸은 결과를 쓰지 않고 로컬 콘솔 큐에서 뺀다.
- 다시 실행으로 고른 칸은 결과가 있어도 돌린다. 다만 다른 Run이 잡았거나, 이 Run이 시작한 뒤(이어서 실행이면 처음 시작한 시각) 다른 Run이 끝낸 칸은 건너뛴다.

## 진행 매트릭스

케이스 × 대상 디바이스의 완료 / 실행 중(실행자 표시) / 남은 칸을 실시간으로 보인다. 일시정지된 Run은 이유를 함께 보인다.

## 완료

- QA 권한자가 사이클을 완료로 표시한다. 확인필요·N/T 칸이 남아 있으면 건수를 경고하고 확인받는다.
- 완료된 사이클은 **새 Run을 받지 않는다.** 보안 규칙·웹 요청·호스트가 함께 막고, 일시정지된 Run의 이어서 실행은 호스트가 막는다. 이미 실행 중인 Run은 끝까지 결과를 올린다. 사람 확정은 계속할 수 있다.
- 완료를 취소해 다시 열 수 있다.
- 사이클 목록은 **"시작 전"·"진행 중"·"완료" 칩**으로 나눈다. 기본은 진행 중이다. 별도 보관함은 없다. 완료 기록은 사이클 간 비교의 기준이라 숨기지 않는다. 개발 서버의 로컬 실행 사이클은 "로컬 실행" 칩에 따로 둔다.

## 삭제

잘못 만든 사이클(빌드·QA 문서·대상 선택 실수)을 지운다.

- QA 권한자만, 사이클 이름을 입력해 확인한다. 지워질 결과·Run·결함 건수를 보인다.
- **완료된 사이클은 먼저 다시 열어야** 지울 수 있다(완료 기록을 실수로 지우지 않게). 실행 중인 Run이 있으면 거부한다.
- 유예 없이 바로 영구 삭제한다. Functions가 하위 문서(케이스 사본·결과·Run·시도·결함·판정 이력)와 Storage `projects/{p}/cycles/{c}/` 아래 증거를 지운다. 클라이언트는 사이클 문서를 직접 지우지 못한다.
- 빌드·QA 문서는 남는다.
