# Agent 실행

호스트 에이전트가 디바이스에서 케이스를 수행하고 판정하는 규칙이다.

코드: 실행 루프 `packages/agent`(`runSteps`·`verifyPoints`·`judge`·`runCase`), 디바이스 `packages/device`, LLM `packages/llm`, Run 진행 `apps/host-agent/src/runCycle.ts`. 실기기 명령은 [dev/device-llm.md](../dev/device-llm.md).

## 호스트와 디바이스

- 호스트 에이전트는 실행자 PC(macOS)에 설치한다. 따로 로그인하지 않고 웹에서 실행자 계정에 연결한다([projects.md](projects.md#호스트-연결)).
- `adb devices`에 잡힌 실기기·에뮬레이터면 쓴다.
- **호스트(1인)당 동시 실행 디바이스는 1대**이고, 한 디바이스는 한 실행만 점유한다. 팀 전체 동시 실행 수 = 실행 중인 팀원 수다.
- 앱 설치·데이터 초기화를 한다.

## 실행 루프

- 케이스의 자연어 스텝을 해석해 디바이스 액션(탭, 입력, 스와이프, 뒤로가기, 홈, 앱 재시작, 대기 등)으로 수행한다.
- 화면 인식은 **접근성 트리(`uiautomator dump`) 우선, 스크린샷 비전 보조**다.
- **환경 조작 액션**: 디바이스 Wi-Fi·모바일 데이터 on/off. 호스트 PC 네트워크는 그대로라 LLM 호출에는 영향이 없다. 네트워크를 끄는 케이스는 **USB 연결 디바이스에서만** 실행하고(Wi-Fi ADB면 Blocked), 케이스가 끝나면 원복한다.
- 예상치 못한 팝업·OS 권한 요청·키보드·로딩은 자가 복구한다. 횟수는 실행 안전장치의 "자가 복구 횟수"이고, 넘으면 Pass를 자동 확정하지 않는다.
- Claude Code 프로세스를 케이스 동안 유지해 실행 오버헤드를 줄인다. 실측(2026-10-22, SM-S711N): 스텝당 약 4.5초, 케이스 81초·호출 16회.

## 스텝 타임라인

스텝마다 액션 종류, 대상(좌표·요소 ID), 입력값(비밀값 마스킹), 의도(Agent 판단), **액션 직전 스크린샷 + 액션 표시**(탭 위치·스와이프 화살표·대상 박스)를 남긴다. 결과 화면은 다음 스텝의 직전 화면으로 대신하고, 마지막 화면과 검증 시점 화면을 따로 저장한다.

## 판정

### 검증 포인트

검증 포인트는 QA 문서를 만들 때 정의·승인한다([qa-doc.md](qa-doc.md#케이스-필드)).

- **트리 포인트**: LLM(Verifier)은 트리에서 **대상 요소만 찾고, 값 비교는 코드가 한다**(dp는 bounds ÷ 화면 밀도). 찾은 요소는 증거로 남긴다.
- **비전 포인트**: Verifier가 화면으로 판정한다.
- 포인트마다 기대 / 확인 방법 / 대상 요소 / 관찰값 / 결과(일치·불일치·판단불가) / 증거를 남긴다.
- 트리에 노드가 없는 요소(예: 선택된 인디케이터 dot)는 셀 수 없어 확인필요로 남는다. 해법은 앱 쪽 testTag다.

### 케이스 판정 집계

- 불일치가 하나라도 있으면 → **Fail**
- 판단불가가 있으면 → **확인필요**
- 모두 일치 → **Pass** (자동 확정 조건은 [results.md](results.md#자동-확정))

앱 크래시는 Fail이다.

### Agent가 Blocked로 두는 경우

- 준비 플로우 실패(로그인 실패 포함)
- 필요한 종류의 계정 없음
- 환경 조작 불가(예: Wi-Fi ADB에서 네트워크 끄기)
- 수동 스텝 대기 타임아웃
- 위험 액션 승인·사람 전용 단계 대기 타임아웃
- 실행 한도 초과
- 환경 오류(서버 무응답)

디바이스 연결 끊김·잠김은 Blocked가 아니라 [일시정지](#일시정지)다.

## 위험 액션

Agent가 액션 직전에 버튼 종류가 아니라 **결과로** 판별하고 두 등급으로 다룬다.

| 등급          | 대상                                                                                                                                                                                                                                                                                       | 처리                                                                                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **승인 필요** | 실제 사람에게 닿음(메시지·초대·공유·공개 게시·친구 추가·전화·SMS), 돈이 움직임(결제·구독·송금·포인트), 되돌릴 수 없음(탈퇴·삭제·나가기·차단), 대상 앱 밖(공유 시트·다른 앱·시스템 설정·권한 허용), 계정·보안 변경(비밀번호 변경·연동 해제·로그아웃), 현실의 일(주문·예약), 판단이 불확실함 | 직전에 멈추고, 실행자가 **승인**(그 액션 1회만 — 다른 요소를 누르려 하면 다시 묻는다)하거나 **직접 실행**(Take over 후 Agent에 반환)                                               |
| **사람 전용** | 본인인증(PASS·통신사·카드·간편인증), SMS·이메일 인증번호, 공동인증서, 생체인증, 캡차, 소셜 로그인, 실제 개인정보 입력                                                                                                                                                                      | Agent는 입력·탭하지 않고 직접 실행만 가능. 이 구간에서는 화면 구조·스크린샷을 LLM에 보내지 않는다(증거 스크린샷은 찍는다). [Agent에 반환] 때 인증 화면이 남아 있으면 계속 기다린다 |

- **사전 승인**: 승인된 케이스 단계에 적힌 승인 필요 액션은 멈추지 않는다. 다만 사람에게 닿거나 돈이 움직이는 액션과 사람 전용은 적혀 있어도 멈춘다.
- **판별**: Agent 판단 + 코드 안전장치(대상 앱 밖 탭, 권한 대화상자, 버튼 글자 키워드, 비밀번호 입력 칸)로 이중으로 본다. 인앱 웹뷰 인증은 케이스 단계에 인증이 있으면 사람 전용으로 멈춘다.
- 테스트 계정 풀의 아이디·비밀번호 로그인(비밀값 플레이스홀더)은 위험 액션이 아니다.
- **승인은 로컬 콘솔에서만** 한다. 웹은 "승인 대기"만 보인다. 응답이 없으면 대기 타임아웃(기본 10분) 뒤 그 케이스는 Blocked("위험 액션 미승인" / "사람 전용 단계 미수행")이고 다음 케이스로 간다.
- 판별 결과·등급·승인자·시각을 스텝 타임라인에 남긴다.

## 수동 스텝

"수동" 표시 스텝에서 Agent가 멈추고 알린다. 실행자가 디바이스에서 직접 한 뒤 "완료"를 누르면 이어서 진행한다. 응답이 없으면 대기 타임아웃 뒤 그 케이스는 Blocked이고 다음 케이스로 간다.

## 실행 안전장치

사용자 본인의 플랜을 쓰므로 폭주를 막는 것이 중요하다. 한도는 프로젝트 설정(`runLimits`)이다. Admin만 바꾸고 다른 멤버는 본다. 호스트가 Run을 시작할 때 읽으므로 진행 중 사이클에도 다음 Run부터 적용된다. 정의는 `packages/shared/src/runLimits.ts`.

| 한도                       | 기본값                                                 | 넘으면                                         |
| -------------------------- | ------------------------------------------------------ | ---------------------------------------------- |
| 케이스당 최대 턴           | 단계 수 × 3 + 10 (준비·원복 플로우는 각자의 스텝 수로) | 케이스 Blocked("실행 한도 초과")               |
| 같은 화면 + 같은 액션 반복 | 3회                                                    | 케이스 Blocked                                 |
| 자가 복구                  | 3회                                                    | 자동 확정하지 않음                             |
| 케이스당 LLM 호출          | 40회                                                   | 케이스 Blocked                                 |
| 케이스당 토큰              | 60만 (실측 평균의 약 3배)                              | 케이스 Blocked                                 |
| Run당 토큰                 | 2,000만                                                | 다음 케이스 전에 Run 일시정지("Run 토큰 한도") |
| 수동 스텝·위험 액션 대기   | 10분                                                   | 케이스 Blocked                                 |

- 케이스 한도는 준비·검증·원복을 포함해 센다.
- **Run당 토큰은 케이스를 끊지 않는다.** 케이스가 끝난 뒤 넘었으면 다음 케이스 전에 일시정지한다. 남은 케이스를 줄줄이 Blocked로 만들지 않으려는 것이다. 이어서 실행해도 그 Run이 이미 올린 결과의 토큰을 더해 세므로, 한도를 올려야 이어 간다.

## 일시정지

케이스 결함이 아니라 실행 환경 탓이고 시간이 지나거나 사람이 고치면 풀리는 문제는 Blocked 대신 **Run을 일시정지**한다.

| 이유                      | 코드                   |
| ------------------------- | ---------------------- |
| 실행자                    | `executor`             |
| 네트워크 끊김             | `network`              |
| 플랜 한도                 | `plan_limit`           |
| Claude Code 로그인 필요   | `not_logged_in`        |
| Claude Code 설치 필요     | `claude_not_installed` |
| Claude Code 업데이트 필요 | `claude_outdated`      |
| 디바이스 잠김             | `device_locked`        |
| 디바이스 연결 끊김        | `device_disconnected`  |
| 호스트 연결 끊김          | `host_lost`            |
| Run 토큰 한도             | `run_limit`            |

- 진행 중이던 케이스는 판정하지 않고 결과를 버린다.
- 실행자가 [이어서 실행]하면 그 케이스를 **처음부터** 다시 실행한다. 멈춘 동안 화면·세션이 바뀌므로 준비 플로우부터 다시 도는 쪽이 결정적이다.
- 재개는 늘 실행자가 한다. 재연결 때 자동 재개는 없다.
- **네트워크 끊김**: 올리지 못한 결과·증거는 로컬 디스크 큐에 두었다가 다시 연결되면 보낸다.

## Claude Code 상태

- Run·QA 문서 생성을 시작하기 전에 Claude Code 설치·로그인·버전을 확인한다. 최소 버전은 모델별 표 `CLAUDE_CODE_MIN_VERSION`(`packages/llm/src/types.ts`)에서 작업이 부르는 모델 중 가장 높은 값이다.
- 문제가 있으면 Run은 해결 방법을 알리고 시작하지 않는다. QA 문서 생성 작업은 대기열에 남겨 두었다가 해결되면 시작한다.
- 플랜 한도는 실패해야만 알 수 있으므로 시작을 막지 않는다. 다음 시작 때 풀어 보고 또 닿으면 다시 일시정지한다. 풀리는 시각은 stream-json의 한도 알림(`rate_limit_event`)에서 먼저 읽고, 없으면 오류 문구에서 읽는다.
