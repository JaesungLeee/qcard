# GitHub 이슈 발행

결함을 프로젝트에 연결한 GitHub 저장소의 이슈로 발행하고, 이슈와 결함의 상태를 맞추는 규칙이다. 결함 자체의 규칙은 [results.md](results.md#결함), 권한·비밀값은 [security.md](../security.md#github-이슈), 고른 이유는 [decisions.md](../decisions.md#결함-트래커는-github-issues)에 있다.

구현돼 있고 qcard GitHub App(`qcard-bot`)도 등록했다. 운영에 배포하면 켜진다([dev/deploy.md](../dev/deploy.md#github-app-결함--이슈-발행), [roadmap.md](../roadmap.md#github-이슈-발행)). 코드는 Functions `apps/functions/src/issues.ts`·`github.ts`, 규칙·템플릿 해석 `packages/shared`(`issues.ts`·`issueTemplate.ts`), 초안 `packages/reporter`, 웹 `apps/web/src/features/issues/`.

## 흐름

1. Admin이 프로젝트에 GitHub 저장소 1개를 연결하고, 스펙별 담당자를 정해 둔다.
2. 결함마다 [이슈 발행]을 누르면 팝업이 열린다. 저장소의 이슈 템플릿 중 하나를 고른다.
3. 요청자의 호스트에서 Claude가 그 템플릿에 맞춘 제목·본문 초안을 쓴다.
4. 사람이 팝업에서 제목·본문·라벨·담당자를 고친 뒤 [발행]한다. qcard GitHub App(`qcard-bot[bot]`)이 이슈를 만든다.
5. 이후 이슈를 닫거나 다시 열면 결함 상태가 바뀌고, qcard에서 결함 상태를 바꾸면 이슈에 반영된다.

## 저장소 연결

- **Admin만**, 프로젝트 설정에서 연결·해제한다. 프로젝트당 **저장소 1개**다. 앱·서버가 다른 저장소인 팀은 GitHub에서 이슈를 옮긴다(transfer). 옮긴 이슈는 동기화가 끊긴다([상태 동기화](#상태-동기화)).
- [GitHub 저장소 연결] → GitHub의 qcard App 설치 화면에서 설치할 저장소를 고른다 → qcard로 돌아와 그 설치에 들어 있는 저장소 중 하나를 고른다.
  - 설치를 돌려받을 때 GitHub 사용자 인가를 함께 받아, **연결하는 사람이 그 저장소에 실제로 접근할 수 있는지** Functions가 확인한다. 설치 ID만으로는 연결하지 않는다(남의 설치를 끌어다 쓰는 것을 막는다). 이 사용자 토큰은 확인에만 쓰고 저장하지 않는다.
  - 조직 저장소는 조직 Admin이 설치를 승인해야 할 수 있다. 승인 대기 중이면 연결할 저장소가 보이지 않는다고 안내한다.
- **공개 저장소**를 고르면 "이슈는 누구나 볼 수 있다. 미공개 스펙 내용이 들어갈 수 있다"를 보이고 확인받는다.
- 연결 정보: 저장소(소유자·이름·저장소 ID), 공개 여부, 설치 ID, 연결한 사람·시각. 저장소 이름·공개 여부는 팝업을 열 때와 공개 전환 웹훅으로 다시 맞춘다.
- 이미 App을 설치한 계정은 설치 화면 대신 [저장소만 고르기]로 사용자 인가만 받고 돌아온다. 돌아올 때까지의 연결 진행(요청자·만료 30분, 확인한 저장소 목록)은 클라이언트가 읽지 못하는 문서에 둔다.
- **해제**: 이미 발행한 이슈와 결함의 연결 주소는 남고, 동기화는 멈춘다. 같은 저장소를 다시 연결하면 그 이슈들은 다시 동기화된다.
- GitHub에서 App을 지우거나 그 저장소를 설치에서 빼면 연결을 "끊김"으로 표시하고 Admin에게 다시 연결하라고 안내한다. 발행과 동기화는 멈춘다.

## 담당자 매핑

- 프로젝트 설정에 **스펙 이름 → GitHub 사용자명(1명 이상)** 표를 둔다. Admin이 고친다.
- 결함의 스펙 이름은 케이스 출처 ID의 앞부분이다(`room-list/TS-003` → `room-list`). 스펙 이름은 버전이 바뀌어도 유지되므로 매핑도 유지된다.
- 표의 스펙 이름 목록은 가장 최근 QA 문서의 스펙 묶음에서 가져온다. 새 스펙은 "미지정"으로 보인다.
- 저장소가 연결돼 있으면 사용자명은 저장소의 **지정 가능한 사람**(assignable users) 목록에서 고른다.

## 발행 팝업

결함 탭의 결함 행, 확정 패널·판정 추적의 결함 영역에 [이슈 발행]이 있다. **QA·Admin만** 보인다. 저장소가 연결돼 있지 않으면 [이슈 발행] 대신 "Admin이 저장소를 연결하면 발행할 수 있다"를 보인다.

### 템플릿 고르기

- 팝업을 열 때마다 연결된 저장소 기본 브랜치의 `.github/ISSUE_TEMPLATE/` 아래 `*.md`·`*.yml`·`*.yaml`을 읽어 목록으로 보인다(`config.yml` 제외). 템플릿의 `name`과 `about`(이슈 폼은 `description`)을 보인다.
- 목록 맨 아래에 **qcard 기본 템플릿**이 늘 있다. 저장소에 템플릿이 없으면 기본 템플릿만 보인다.
- 읽지 않는 것: 조직 `.github` 저장소의 공용 템플릿, 예전 형식 `.github/ISSUE_TEMPLATE.md`. 이런 팀은 저장소에 템플릿을 두거나 기본 템플릿을 쓴다.
- 템플릿을 고르면 바로 초안을 요청한다.

### 템플릿 해석

GitHub는 API로 만드는 이슈에 템플릿을 적용하지 않는다. qcard가 템플릿을 읽어 GitHub 웹과 같은 모양으로 채운다.

| 형식                    | qcard가 하는 일                                                                                                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Markdown(`.md`)         | frontmatter의 `title`(제목 접두어)·`labels`·`assignees`를 읽고, 본문 Markdown을 채운다                                                                                                            |
| 이슈 폼(`.yml`·`.yaml`) | `body`의 입력 요소(`input`·`textarea`·`dropdown`·`checkboxes`)를 필드로 채우고 `### 라벨` + 값으로 본문을 만든다. 빈 값은 `_No response_`, 체크박스는 `- [x] 항목`. `markdown` 요소는 넣지 않는다 |
| 해석할 수 없는 템플릿   | 목록에 "읽을 수 없음"으로 보이고 고를 수 없다                                                                                                                                                     |

- 이슈 폼의 `validations.required` 필드가 비어 있으면 팝업에 표시한다. GitHub API는 필수 필드를 검사하지 않으므로 **발행은 막지 않는다**.
- `dropdown`은 템플릿에 있는 선택지 값만 쓴다.

### 초안

- 템플릿을 고르면 **요청자의 호스트**에 이슈 초안 작업(`issue_draft`)을 만든다. 호스트의 Claude(Reporter)가 템플릿 구조에 맞춰 제목과 본문(이슈 폼이면 필드별 값)을 쓴다. 사용량은 요청자의 플랜에서 나간다.
- Claude에 넘기는 것: 결함(제목·심각도·재현 절차·기대/실제 결과), 케이스(TC ID·출처·요구사항 ID·제목·절차·기대 결과), 디바이스·OS 빌드, 앱 버전·빌드 번호, 사이클 이름, 고른 템플릿. **스크린샷·화면 구조는 넘기지 않는다.**
- **넘긴 정보에 없는 값은 비워 둔다.** 원인 분석·서버 로그·사용자 영향 같은 칸을 추측으로 채우지 않는다. 비운 필드는 팝업에서 "직접 채울 칸"으로 표시한다.
- 호스트가 꺼져 있으면 "호스트를 켜면 초안을 만든다"를 보이고 기다린다. [초안 없이 작성]을 누르면 템플릿 원문(이슈 폼이면 빈 필드)으로 바로 편집한다.
- 초안은 결함마다 요청자별로 마지막 하나만 기억한다(작업 id `draft-<사이클>-<결함>-<요청자>`). 팝업을 닫았다 열면 마지막 초안을 다시 보인다. 이미 발행한 결함은 초안을 요청할 수 없다.
- 호스트는 초안 작업을 QA 문서 생성과 따로 처리한다. 생성이 오래 걸려도 초안은 기다리지 않는다.

### qcard 기본 템플릿

결함 필드로 채울 수 있는 항목만 둔다. 정의는 `packages/shared`에 둔다.

```markdown
## 요약

## 환경

- 앱 버전:
- 디바이스 / OS:
- QA 사이클:

## 재현 절차

1.

## 기대 결과

## 실제 결과

## 관련 케이스

- TC ID / 출처 / 요구사항:

## 심각도
```

저장소에 `bug` 라벨이 있으면 `bug`를 붙인다.

### 편집과 발행

- 팝업에서 제목·본문(이슈 폼이면 필드별)·라벨·담당자를 고친다.
- **라벨**: 템플릿의 라벨 중 저장소에 있는 것만 미리 고른다. 없는 라벨은 "저장소에 없음"으로 보이고 빼고 발행한다. 저장소의 기존 라벨에서 더 고를 수 있다. qcard는 라벨을 만들지 않는다.
- **담당자**: 기본값은 담당자 매핑의 그 스펙 담당자, 없으면 템플릿 `assignees`. 저장소의 지정 가능한 사람만 남기고 나머지는 "지정할 수 없음"으로 보인다. 바꿀 수 있다. 최대 10명.
- 본문 끝에는 **코드가** 다음 줄을 붙인다. 팝업에서 고칠 수 없다.

  ```
  ---
  qcard 결함 D-3 · 사이클 "1.2.0 회귀" · 판정 추적: https://qcard.dev/…
  reported by @요청자 via qcard
  ```

  판정 추적 링크는 qcard 프로젝트 멤버만 열 수 있다. 스크린샷은 이 링크로 본다(GitHub API로 이슈에 이미지를 올릴 수 없다).

- 공개 저장소면 [발행] 앞에 공개 경고를 다시 보이고 확인받는다.
- [발행]하면 Functions가 App 설치 토큰으로 이슈를 만든다. 작성자는 `qcard-bot[bot]`이다.
- **결함 하나에 이슈 하나**다. 발행 중이면 버튼을 막고, 이미 발행했으면 [이슈 발행] 대신 이슈 링크(`#123`)와 상태를 보인다. 두 번 발행하지 않도록 Functions가 트랜잭션으로 확인한다.
- 발행이 실패하면(권한 없음, 저장소 없음, GitHub 오류) 이유를 보이고 편집 내용은 팝업에 남긴다.

## 결함에 남기는 것

결함에 이슈 연결(저장소 ID, 이슈 번호, 주소, 이슈 상태, 발행한 사람·시각)을 남긴다. 결함 탭에 **이슈** 컬럼(`#123` 링크 + 열림·닫힘)이 생긴다. 이슈 연결은 Functions만 쓴다(보안 규칙).

## 상태 동기화

양방향이다. qcard 결함 상태는 open·fixed·closed, GitHub 이슈는 open·closed(이유: completed·not planned·duplicate)다.

**GitHub → qcard** (App 웹훅):

| GitHub 이벤트               | 결함이 open | 결함이 fixed | 결함이 closed |
| --------------------------- | ----------- | ------------ | ------------- |
| 닫힘(completed)             | → fixed     | 그대로       | 그대로        |
| 닫힘(not planned·duplicate) | → closed    | → closed     | 그대로        |
| 다시 열림                   | 그대로      | → open       | → open        |

- **이슈 삭제**: 이슈 연결을 "삭제됨"으로 두고 상태는 그대로다. 다시 발행할 수 있다.
- **다른 저장소로 옮김**(transfer): 새 주소를 남기고 "옮겨짐, 동기화 안 됨"으로 표시한다. 상태는 그대로다.

개발자가 고쳐서 닫으면 fixed가 되고, QA가 재테스트한 뒤 qcard에서 closed로 바꾸는 흐름이다.

**qcard → GitHub** (결함 상태를 바꿀 때):

| qcard에서 바꾼 상태 | 이슈에 하는 일                                                    |
| ------------------- | ----------------------------------------------------------------- |
| closed              | 열려 있으면 닫는다(completed). 코멘트 "QA 확인 완료 (@바꾼 사람)" |
| open                | 닫혀 있으면 다시 연다. 코멘트 "QA에서 다시 열림 (@바꾼 사람)"     |
| fixed               | 상태는 그대로 둔다. 코멘트 "qcard에서 fixed로 표시 (@바꾼 사람)"  |

- 이슈가 연결된 결함의 상태는 **Functions를 거쳐서만** 바꾼다(연결이 해제·끊김이거나 이슈가 삭제·이전돼도 그렇다. 그때는 GitHub를 부르지 않고 qcard만 바꾼다). GitHub 호출이 실패하면 qcard 상태도 바꾸지 않고 이유를 보인다. 이슈 상태는 바꿨는데 코멘트만 실패하면 qcard도 바꾼다. 심각도는 이슈와 상관없이 그대로 바꾼다.
- 루프를 막는다: qcard가 바꾼 이슈 상태가 웹훅으로 돌아오면 위 표에서 "그대로"가 된다(예: qcard closed → 이슈 닫힘(completed) → 결함 closed 그대로).
- 이슈가 연결된 결함의 상태 변경에 주체(qcard 사용자 또는 GitHub 사용자명)와 시각을 남긴다.
- 동기화하지 않는 것: 제목·본문·라벨·담당자·코멘트, 이슈 삭제·이전 이후의 상태, 연결이 해제·끊김인 동안의 변화.
- GitHub는 실패한 웹훅을 자동으로 다시 보내지 않는다. 놓친 이벤트는 다음 변경 때까지 어긋날 수 있다([roadmap.md](../roadmap.md#알려진-빈틈)).

## 삭제

- **사이클 삭제**·**프로젝트 영구 삭제**: 결함과 이슈 연결 색인을 지운다. **GitHub 이슈는 지우지 않는다.** 이슈 속 판정 추적 링크는 열리지 않게 된다. 삭제 확인 화면에 발행한 이슈 수를 보인다.
- 삭제 유예 중인 프로젝트는 발행·동기화를 멈춘다.
