# 결과와 QA 시트

사이클의 결과를 보고, 확정하고, 공유하는 규칙이다. **QA 시트는 웹이 유일한 형태다.**

코드: 집계 `packages/data/src/logic.ts`, 판정 `packages/shared/src/verdict.ts`, 화면 `apps/web/src/features/qa-sheet`.

## QA 시트 구성

사이클 단위 화면이다. 탭마다 고유 주소(`?tab=`)가 있다.

| 탭            | 내용                                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 요약          | 프로젝트명, QA 문서 버전, 대상 빌드(앱 버전·빌드 번호), 테스트 기간, 대상 디바이스, 판정별 건수·통과율(전체/디바이스별), 주요 결함 |
| 테스트 케이스 | 케이스와 디바이스별 결과(아래 컬럼). 결과 칸을 열면 판정 추적                                                                      |
| 결함          | 결함 ID, 제목, 심각도, 관련 TC ID, 디바이스/OS, 재현 절차, 기대/실제 결과, 상태, GitHub 이슈                                       |
| 추적성        | 요구사항 ID × TC ID, 요구사항별 커버리지·통과 여부                                                                                 |
| 환경          | 디바이스(모델, OS 버전, 해상도), 빌드 정보, 테스트 계정(마스킹), 서버 환경                                                         |

실제 결과는 컬럼으로 두지 않는다. **Fail·확인필요 칸에서만 한 줄 요약**을 보이고, 전체는 판정 추적에서 본다.

판정 칸 색: Pass 초록, Fail 빨강, Blocked 주황, N/A·N/T 회색, 확인필요 노랑. 판정 값의 뜻은 [concepts.md](../concepts.md#판정).

## 판정 추적

케이스 × 디바이스 결과에서 **행동 의도 → 스텝 타임라인(액션 표시 스크린샷) → 검증 포인트(기대·관찰값·증거) → 판정 이유**까지 따라간다.

## 자동 확정

다음을 모두 채우면 Agent Pass를 자동 확정하고, 하나라도 못 채우면 확인필요로 둔다. 채운·못 채운 조건 목록을 결과에 남긴다.

1. 모든 검증 포인트가 일치 (`all_match`)
2. 모든 검증 포인트를 접근성 트리로 확인 — 비전으로만 확인한 포인트가 있으면 안 됨 (`tree_only`)
3. Take over·스텝 건너뛰기 없음 (`no_takeover`)
4. 자가 복구 횟수가 한도 안 (`within_retry`)

2번은 완화하지 않는다. 비전 판정이 사람 판정과 얼마나 맞는지 데이터가 쌓이면 다시 본다([roadmap.md](../roadmap.md)).

## 사람 확정

- Fail·Blocked·확인필요는 사람이 확정한다. 자동 확정된 Pass도 사람이 뒤집을 수 있고, 뒤집힌 자동 Pass는 결과에 표시한다.
- 보안 규칙이 **판정자 = 로그인 사용자**와 서버 시각을 강제하고, 판정 변경 이력은 바꿀 수 없는 로그로 남긴다.

## 수동 케이스 결과

- 웹 그리드에서 판정·실제 결과·스크린샷 첨부를 입력한다.
- **스크린샷은 선택이다.** 화면으로 확인할 수 없는 케이스, 다른 사람 폰에서 결과가 나는 케이스가 있고, 본인인증 화면처럼 올리면 안 되는 화면이 있어서다. Fail·Blocked에서 첨부가 없으면 권유 문구만 보이고 저장은 막지 않는다.
- 5장, PNG/JPEG/WebP, 한 장 10MB까지. 붙여넣기도 된다. 판정을 확정할 때만 바뀌고 이력에 장수가 남는다. Storage `cycles/{c}/manual/` 아래라 사이클·프로젝트 삭제 때 함께 지워진다.

## 결함

- Fail 결과(판정 추적, 확정 패널)에서 결함을 만든다. TC ID·디바이스/OS·빌드·재현 절차·기대/실제 결과·증거(결과 주소)를 미리 채운다.
- 번호 `D-n`은 사이클 안에서 이어진다(보안 규칙이 번호를 확인).
- 심각도(critical·major·minor·trivial)와 상태(open·fixed·closed)를 결함 탭에서 바꾼다.
- 결함이 없는 Fail 칸을 사이클 카드·요약·케이스 그리드에 표시한다.
- 결함마다 연결한 GitHub 저장소에 이슈로 발행할 수 있다. 이슈가 연결된 결함의 상태는 이슈와 양방향으로 맞춘다([issues.md](issues.md)).

## 공유

웹 화면 주소가 곧 공유 링크다. QA 시트(탭 포함)·판정 추적 결과마다 고유 주소가 있고, 로그인하지 않았으면 로그인 후 그 주소로 돌아오며, 멤버가 아니면 보안 규칙이 막는다. [링크 복사] 버튼, 별도 리포트 화면, 멤버 밖 공개 링크는 두지 않는다.
