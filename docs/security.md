# 보안과 데이터 처리

qcard는 여러 팀이 쓰는 공개 서비스다. 이 문서는 데이터가 어디로 가고 누가 무엇을 읽고 쓸 수 있는지 정한다. 사용자에게 보이는 고지는 웹의 `/privacy`·`/terms`(`apps/web/src/features/legal/`)에 있으며, 이 문서와 어긋나면 안 된다.

## Anthropic으로 보내는 데이터

- 스펙 문서 원문(미공개 기획서)
- 실행 중 디바이스 스크린샷과 화면 구조(테스트 계정 정보, 개인정보성 데이터가 화면에 보일 수 있음)
- 이슈 초안을 만들 때 결함·케이스 텍스트와 이슈 템플릿(스크린샷·화면 구조는 보내지 않음)

## LLM 호출 경로

**사용자 본인의 Claude Code를 거친다.** 각 사용자 PC에 설치·로그인된 Claude Code CLI를 호스트가 헤드리스(`claude -p`)로 실행하고, 비용은 그 사용자의 Claude 구독 플랜에서 차감된다. 다른 선택지와 버린 이유는 [decisions.md](decisions.md#llm은-사용자-본인의-claude-code로)에 있다.

경계:

- Anthropic은 구독 플랜의 OAuth 인증을 Claude Code와 Claude.ai 전용으로 두고, 그 토큰을 다른 제품에서 쓰거나 제3자가 사용자 대신 요청하는 것을 허용하지 않는다. 그래서 qcard는 **Agent SDK·OAuth 토큰을 쓰지 않고**, 사용자가 직접 설치·로그인한 수정하지 않은 Claude Code를 헤드리스 모드로 실행한다.
- qcard는 Claude 자격 증명을 **읽거나 저장·전달하지 않는다.** 요청은 그 사용자의 PC에서, 그 사용자의 요청에 대해서만 나간다.
- **작업은 요청자 본인의 호스트만 처리한다.** 다른 사용자의 행동이 내 플랜을 쓰지 않는다. 계정 공유·대리 처리 경로는 두지 않는다.
- 호스트는 `claude`를 실행할 때 `ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`을 넘기지 않는다. 사용자 PC에 다른 용도의 키가 있어도 API로 과금되지 않게 하기 위해서다.
- **지원하는 로그인은 Claude 구독 플랜뿐이다.** Console 계정·API 키·Bedrock·Vertex로 로그인한 Claude Code(API 크레딧 과금)는 상태 표시·사전 점검·한도 처리에서 따로 다루지 않는다. 플랜 이름은 Claude Code가 알려 주는 값을 그대로 보이고, 특정 플랜의 한도 구조(5시간·주간 등)를 가정하지 않는다.
- API 키 구현(`LLM_PROVIDER=api`)과 녹화·재생은 개발·테스트용이다. 이 저장소의 테스트는 가상 앱과 합성 화면만 쓴다.

정책 확인이 남아 있다. 2026-10-24 조사에서 조건부 허용으로 판단했고, Commercial Terms 동의와 Anthropic 서면 확인은 공개 출시 전에 끝낸다([roadmap.md](roadmap.md#공개-출시-조건)). 그때까지 지킬 조건은 다음과 같다.

- 바이너리를 수정하지 않고, 내장 인증 방식을 제거·비활성화하지 않는다.
- 사용 비용을 대신 내거나 중개하지 않는다. 각자 본인 플랜을 쓴다.
- Claude.ai 로그인을 qcard에 넣거나 자격 증명·세션 토큰을 수집하지 않는다.
- Claude Code 이름·로고를 제품명·로고에 쓰지 않는다.

### Claude Code 실행 방식

- 내장 도구(셸·파일 편집·웹 등)를 모두 끄고, MCP 서버를 불러오지 않으며, 사용자·프로젝트 설정을 읽지 않고, 세션을 디스크에 남기지 않는다. 저장소 밖의 빈 폴더에서 실행한다.
- 시스템 프롬프트는 qcard 것으로 바꾼다. 모델이 할 수 있는 일은 qcard가 정한 출력 형식으로 답하는 것뿐이다.

### 전송 제한

- 대상 앱이 포그라운드가 아니면 스크린샷을 보내지 않는다. 호스트 코드가 강제한다.
- **사람 전용 구간**(본인인증·인증번호 등)에서는 화면 구조·스크린샷을 LLM에 보내지 않는다. 증거 스크린샷은 찍어 Storage에 올리므로 실행자가 입력한 개인정보가 프로젝트 멤버에게 보일 수 있다. 본인인증 우회가 있는 QA 빌드를 권장한다.
- 개인 플랜에는 ZDR(데이터 미보존)이 없다. 보낸 데이터는 **실행한 사용자 Claude 계정의 데이터 정책**을 따른다. 프로젝트를 만들거나 참여할 때 이를 안내하고 확인받으며, 학습 사용을 끄도록 권한다. 실데이터를 넣을지는 프로젝트 Admin이 판단한다.
- 호스트는 LLM에 보낸 화면 구조 텍스트를 저장하지 않는다. 스텝 타임라인의 증거 스크린샷이 보낸 화면의 기록을 대신한다.

## 인증과 권한

- **웹 로그인**은 GitHub 단일(Firebase Auth)이고, 웹 로그인 페이지에서만 한다.
- **프로젝트 격리**는 Firestore·Storage 보안 규칙(`firebase/`)이 강제한다. 프로젝트 간 격리는 에뮬레이터 규칙 테스트로 `pnpm verify`에서 검증한다.
- **역할**: Admin / QA(편집·실행·확정) / Viewer(조회). 보안 규칙이 강제한다.
- **호스트 자격**: 비밀값은 실행자 PC의 macOS 키체인에만 두고 서버에는 해시만 저장한다. 호스트는 켤 때마다 이 자격으로 짧은 수명의 호스트 토큰(호스트 클레임 포함)을 받는다. 보안 규칙은 호스트 쓰기마다 연결 상태를 확인해, 연결을 해제한 PC의 쓰기를 즉시 막는다.
- **Agent 기록**(Run, Agent 판정 결과, 이전 시도, 스크린샷)은 그 Run을 실행한 사용자의 호스트만 쓸 수 있다. Run에 실행자 uid를 남기고 보안 규칙이 확인한다. Run이 실행 중인지는 보지 않는다(업로드 큐로 늦게 도착한 결과를 받아야 하므로).
- **사람**은 결과 칸에서 판정·메모·첨부 스크린샷만 바꾸고 Agent 증거(단계·검증 포인트·Run)는 못 바꾼다. 사람 판정은 판정자 = 로그인 사용자, 서버 시각, 바꿀 수 없는 이력으로 강제한다.
- 실행자가 자기 호스트를 통해 Agent 결과를 조작할 여지는 있다. 프로젝트 멤버 간 신뢰를 전제로 감수한다(다른 프로젝트에는 영향이 없다).

## GitHub 이슈

결함을 GitHub 이슈로 발행하는 경로다. 동작 규칙은 [product/issues.md](product/issues.md).

- **권한은 qcard GitHub App 하나로 받는다.** 저장소 권한은 Issues 읽기·쓰기, Contents 읽기, Metadata 읽기뿐이다. OAuth `repo` 스코프(모든 비공개 저장소 쓰기)는 요구하지 않는다. Contents 읽기는 저장소 코드 전체를 읽을 수 있는 권한이지만 qcard는 `.github/ISSUE_TEMPLATE/`만 읽는다. 설치할 때 필요한 저장소만 고르라고 안내한다.
- **GitHub 호출은 Functions만 한다.** 웹·호스트는 GitHub 토큰을 갖지 않는다. 설치 토큰은 호출할 때마다 받아 쓰고(1시간 수명) 저장하지 않는다.
- **비밀값**: App 비밀 키, 웹훅 비밀값, App 클라이언트 비밀값은 Secret Manager에 두고 Functions만 읽는다. 저장소에도 Firestore에도 두지 않는다.
- **저장소 연결 확인**: 설치 ID만으로 연결하지 않는다. 연결하는 Admin의 GitHub 사용자 인가로 그 사람이 저장소에 triage 이상 권한(이슈를 닫고 열 수 있음)이 있는지 확인한 뒤 연결한다. 읽기 권한만 있는 사람은 qcard-bot을 통해 자기 권한보다 많은 일을 하게 되므로 연결하지 못한다. 이 사용자 토큰은 저장하지 않는다.
- **웹훅**은 `X-Hub-Signature-256` 서명을 확인한 요청만 받는다. 이슈 ↔ 결함 색인(`issueLinks`)과 결함의 이슈 연결은 Functions만 쓰고, 이슈가 연결된 결함의 상태도 Functions를 거쳐서만 바뀐다(보안 규칙).
- **발행은 QA·Admin만**, 저장소 연결과 담당자 매핑은 Admin만 한다.
- **GitHub로 나가는 데이터**: 사람이 검토한 이슈 제목·본문, 라벨·담당자, 요청자의 GitHub 사용자명, qcard 결함 번호·사이클 이름·판정 추적 링크. 스크린샷은 보내지 않는다(링크는 qcard 멤버만 연다).
- **공개 저장소**는 연결할 때와 발행할 때 "누구나 볼 수 있다"를 보이고 확인받는다. 미공개 스펙 내용이 이슈에 들어갈 수 있다는 판단은 발행하는 사람이 한다.
- 이슈는 작성자 `qcard-bot[bot]`으로 만들어지고, 발행한 사람은 본문 끝에 남는다.

## 테스트 계정 비밀값

- 웹에서 등록한 비밀번호·TOTP 시드는 Functions가 **Cloud KMS로 암호화**해, 보안 규칙상 클라이언트가 읽을 수 없는 Firestore 컬렉션에 둔다. 쓰기·읽기는 Functions만 한다. 웹은 저장한 값을 다시 보여 주지 않는다.
- **그 계정을 리스한 실행 중 Run의 실행자 호스트에만** 배정 응답으로 복호화해 전달하고, 꺼낼 때마다 감사 로그(계정·Run·호스트·사용자·시각)를 남긴다. 호스트는 메모리에만 두고 반납·Run 종료 때 버린다.
- Agent에는 로그인 ID와 플레이스홀더(`{{secret.password}}`, `{{secret.totp}}`)만 가고, 실제 값은 드라이버가 입력 직전에 넣는다. TOTP는 그 시각의 코드를 계산한다.
- LLM 프롬프트·화면 구조·로그·사고 로그·스텝 타임라인에서 비밀값과 같은 텍스트를 가린다. 로그인 ID는 화면에 그대로 보이는 값이라 가리지 않는다. 비밀번호 칸은 화면에서 가려지므로 스크린샷은 따로 가리지 않는다.
- 같은 프로젝트의 QA 역할은 실행을 통해 평문을 얻을 수 있다. 테스트 계정은 팀이 공유하는 값이라는 전제다. 등록 화면에서 **실제 서비스 계정 대신 테스트 전용 계정**을 쓰라고 안내한다.

## 로컬 콘솔 보호

- `127.0.0.1`에만 바인딩한다.
- 호스트가 일회용 토큰 URL로 브라우저를 열고, 세션 쿠키(HttpOnly, SameSite=Strict)로 바꾼다.
- 웹에서 여는 경우 일회용 주소(2분·1회)는 본인만 읽을 수 있는 호스트 문서로만 전달한다.
- 모든 HTTP·WebSocket 요청에서 Host·Origin 헤더를 검사해 다른 웹페이지의 요청과 DNS 리바인딩을 막는다.

## 저장과 삭제

- 라이브 화면은 실행자 PC 밖으로 보내지 않는다. 클라우드에는 증거 스크린샷만 저장한다(서울 리전).
- 수동 결과에 사람이 첨부한 스크린샷은 웹에서 Storage로 바로 올라가고 LLM에는 보내지 않는다.
- QA 문서·스펙·판정 이력은 지우지 않는다. 스펙 스냅샷과 빌드는 덮어쓸 수 없다(Storage 규칙). 예외는 둘이다.
  - **사이클 삭제**: 유예 없이 그 사이클의 Firestore 문서와 Storage 증거를 바로 지운다. 빌드·QA 문서는 남는다.
  - **프로젝트 삭제**: 30일 유예 뒤 Firestore 문서(테스트 계정·암호화된 비밀값 포함)와 Storage 파일을 영구 삭제한다.
- 지운 Storage 파일은 버킷 소프트 삭제로 최대 7일 더 남는다. 실행자 PC의 빌드 캐시·업로드 큐와 Anthropic으로 보낸 데이터는 qcard가 지우지 못한다. 개인정보처리방침에 적혀 있다. GitHub에 발행한 이슈도 지우지 못한다(개인정보처리방침에 있다).
- 탈퇴한 멤버는 즉시 접근할 수 없다. 그 사람이 남긴 판정·이력은 남는다.
