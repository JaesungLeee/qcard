# 스펙 형식

qcard가 읽는 `spec.md`의 형식이다. 파서는 `packages/spec/src/parse.ts`이고 LLM 없이 결정적으로 읽는다. 사용자용 안내는 웹 `/guide/spec`(`apps/web/src/features/guide/SpecGuidePage.tsx`)에 있으며, 형식을 바꾸면 둘을 함께 고친다. 예시는 가상 앱 하루콩의 [onboarding-flow/spec.md](../packages/fixtures/spec/onboarding-flow/spec.md).

## 폴더

```
docs/specs/
├─ onboarding-flow/
│   ├─ spec.md        ← 읽는 파일
│   └─ plan.md …      ← 무시
└─ room-list/
    └─ spec.md
```

- 폴더 이름이 **스펙 이름**이고, 요구사항·출처 ID의 접두어가 된다(`room-list/FR-002`, `room-list/TS-003`).
- 앱 버전마다 폴더 전체를 올린다. 빠진 스펙의 케이스는 "삭제"가 된다.

## 읽는 것

### 머리말

```md
**버전**: 1.3.0
**기준 PRD 버전**: 2.0.0
**상태**: CREATED
**최종 수정일**: 2026-09-20
```

여기서 "PRD"는 사용자 팀의 기획 문서다.

### 요구사항

줄 맨 앞의 굵은 ID 목록 항목만 읽는다. 들여쓴 줄은 개정 메모 속 언급이라 뺀다.

```md
- **FR-001**: 시스템은 반드시 첫 화면을 보여 준다. (근거: PRD [SCR-001])
- **UX-002**: 다음으로 가는 버튼은 늘 활성 상태다.
```

`(근거: …)`는 본문에서 떼어 따로 둔다. FR·UX 모두 요구사항이 되지만 **케이스가 되지는 않는다.** 시나리오 표의 「관련 FR」로 연결해 추적성·커버리지를 본다.

### 시나리오 표

`### 유저 플로우 N - 제목` 아래의 표를 읽는다. 유저 플로우가 QA 시트의 세부 기능이 된다.

```md
| ID     | 시나리오 | Given | When | Then | 관련 FR        |
| ------ | -------- | ----- | ---- | ---- | -------------- |
| TS-001 | …        | …     | …    | …    | FR-001, FR-005 |

| ID     | 상황 | 처리 | 관련 FR |
| ------ | ---- | ---- | ------- |
| EC-001 | …    | …    | FR-002  |
```

- **TS 행**: Given → 사전조건·준비 플로우, When → 테스트 절차, Then → 기대 결과·검증 포인트.
- **EC 행**: 상황 → When, 처리 → Then. Given은 비어 있다.
- 칸 안의 `|`는 `\|`로 쓴다.
- Then(EC는 처리)이 비면 경고한다.
- 행마다 출처 위치(헤딩 경로·줄)와 내용 해시를 둔다. 해시가 버전 매칭의 기준이다([product/qa-doc.md](product/qa-doc.md#버전-매칭과-id-이어받기)).
- 측정 가능한 성과(SC)는 케이스로 만들지 않는다.

## ID 규칙

출처 ID 매칭이 기대는 약속이다. 스펙 작성자와 합의해야 한다.

- **지운 TS·EC ID를 다시 쓰지 않는다.**
- 시나리오의 뜻이 바뀌면 고치지 말고 새 ID로 추가한 뒤 예전 행을 지운다.
- 표현만 다듬어도 그 행은 "변경"으로 판정돼 다시 만들어지고 다시 승인해야 한다.
- 같은 ID가 두 번 나오면 앞의 것을 쓰고 경고한다.

## 확인 방법

```sh
pnpm --filter @qcard/spec check <docs/specs 폴더> [--prev <이전 버전 폴더>]
```

개수·경고와 이전 버전 대비 동일·변경·신규·삭제를 보인다. 자세한 것은 [dev/spec-qadoc.md](dev/spec-qadoc.md).

## 앱 쪽 권장 사항

자동 확정은 접근성 트리로 확인한 포인트에만 하므로, 앱이 요소를 트리에 드러낼수록 사람이 볼 일이 줄어든다.

- Compose 앱은 `testTagsAsResourceId = true`를 켜고 주요 요소에 `Modifier.testTag("...")`를 단다.
- 이미지 버튼에는 `contentDescription`을 단다.
